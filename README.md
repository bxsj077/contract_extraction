# 前后向合同智能解析与履约风险审查系统

当前版本已从单合同“文档解析与证据定位层”升级为项目级前后向合同审查平台。原 `contract-extract` 入口继续保留。

## 项目级审查快速开始

推荐目录结构如下。一级目录名称就是前向合同编号；前向可包含主合同及附件，后向允许任意多份合同：

```text
合同根目录/
├─ JSNJA2513970CGN00/
│  ├─ 前向/
│  │  ├─ 前向主合同.pdf
│  │  └─ 技术附件.pdf
│  ├─ 后向/
│  │  ├─ 后向合同A.pdf
│  │  └─ 后向合同B.pdf
│  └─ 收入收款计划/
│     └─ 收入收款计划.xls
└─ JSNJA2600045CGN00/
   ├─ 前向/
   └─ 后向/
```

批量处理并导出精简审查工作簿。固定保留项目汇总、合同解析、时间及收入计划复核、设备未覆盖风险、待复核及人工纠正；仅在存在实施内容差异时增加对应工作表：

```powershell
cd C:\Users\keyan\Documents\contract_extraction
python -m pip install -e .
contract-review --input "C:\合同根目录" --output "C:\合同审查结果"
```

### 收入/收款计划复核规则

- 支持 `.xlsx`、Excel 2003 SpreadsheetML 格式的 `.xls`，以及 `.xml`。
- 收入计划读取“起始日期、终止日期”，收款计划读取“合同履约起始日期、合同履约截止日期”。
- 使用所有有效计划行的最早开始日期和最晚截止日期，与前向合同履约起止日期比较。
- 日期完全相同输出“完全一致”；默认偏差不超过 31 天输出“基本一致，需复核偏差”；超过容差输出风险提示。
- 合同没有可确定的履约起止日期、计划文件无法解析或计划日期缺失时，不猜测日期，直接进入待人工复核。

### 设备、材料和服务对象清单

清单按合同性质分为三类，避免把运维设备或备件误判为采购交付：

| 清单性质 | 典型内容 | 对比方式 |
|---|---|---|
| 采购交付清单 | 设备、材料、软件许可、工程量清单 | 比较名称、型号、单位和数量 |
| 维保/服务对象清单 | 服务器资源、交换机资源、维保设备范围 | 检查后向是否完整覆盖前向服务对象 |
| 现场备件库清单 | CPU、内存、硬盘、阵列卡、交换机整机等应急备件 | 作为后向履约保障要求单独列示，不认定为货物采购 |

每条清单直接带有“判断结果、风险等级、风险说明和证据编号”，Excel 中不再重复生成一套差异行。

### 审查工作簿

| 工作表 | 内容 |
|---|---|
| 项目审查汇总 | 处理状态、总体风险、前向设备未覆盖数、计划差异及待复核数量 |
| 合同解析结果 | 前后向合同基本信息、签订日期、服务期/工期、起算条件、到货/初验/终验节点和关键条款 |
| 时间及收入计划复核 | 前后向工期节点差异，以及收入/收款计划与合同履约期偏差 |
| 设备未覆盖风险 | 逐份解析所有后向合同后汇总清单，优先按“型号+数量”匹配，型号缺失时按标准化名称/同义实施项+数量匹配；仅展示未覆盖或数量不足项 |
| 实施内容差异 | 仅在存在集成实施内容差异时生成 |
| 待复核及人工纠正 | 自动复核提示和已保存的人工纠正记录 |

“合同解析结果”中的“工期数值”和“工期单位”已合并为一列“工期”：明确数值显示为 `90天`、`12个月`；合同仅约定“按招标文件及投标文件执行”等文字时，保留该文字结论，不强制转成数值。

每次命令行审查会同时生成两类文件：

```text
<审查结果目录>\前后向合同履约风险审查_全量_<时间戳>.xlsx
<审查结果目录>\分项目审查结果\<项目编码>_前后向合同履约风险审查_<时间戳>.xlsx
```

全量版包含数据库内全部项目；分项目版保持相同的工作表结构，但每份文件只含一个项目。Web 首页的“导出审查结果”下载全量版，项目列表中的“导出本项目”下载对应项目的独立版本。

示例项目 `XYJAJSNJA260500307` 的验证结果：前向合同履约期为 `2026-04-16` 至 `2027-04-15`，收入和收款计划均为 `2026-04-01` 至 `2027-03-31`，开始、截止日期均提前 15 天；前后向 8 项维保资源全部覆盖，后向另提取 42 行现场备件要求。

## 第一层兼容入口

面向“一个合同号一个文件夹、文件夹内一个或多个 PDF”的本地批处理项目。源 PDF 只读，OCR、缓存、JSON 和 Excel 全部写入独立输出目录。

## 已实现

- 原生文本层质量检查；质量不足时整页 300DPI 本地 OCR。
- 签章尾页自动执行 600DPI 局部增强思路：利用红色通道削弱红章，提高被印章遮挡日期的识别率。
- 合同性质仅输出 `运维类`、`集成实施类` 或空值；运维类仍提取明确的服务期、维保对象及现场备件要求，但不执行建设工期和实施责任差异规则。
- 可读取 Excel 2003 SpreadsheetML（扩展名 `.xls`）及 `.xlsx` 收入/收款计划，并复核计划起止日期与前向合同履约期的偏差。
- 区分采购交付清单、维保/服务对象清单和现场备件库清单；前后向差异直接回填到每条清单行，避免重复导出一套差异明细。
- 支持无“设备清单/报价清单”标题、以单位名称分组的跨页采购表；兼容“数量在前、单位在后”（如 `73台`）、跨页续表、序号重置及型号换行。
- 支持“采购内容、数量、单位、品牌、型号”和无品牌型号的简式清单。多后向项目会逐份保留解析结果，再汇总同型号设备数量与前向清单比较；型号因OCR附加尾码或轻微截断时使用受控相似匹配。
- 到货节点同时识别“设备到货、硬件供货、完成供货、交货”等措辞，并优先保留带明确日期或相对期限的条款。
- 集成实施类抽取工期、工期起算方式、具体日期、预计结束日期、到货/安装/部署/调试/上线/试运行/验收/交付/质保节点、服务内容、乙方义务和关键条款。
- 甲方、乙方、其他方签约日期分别留列，并给出合同签约日期。
- 三方合同只有部分签约日期时，可按配置用已识别日期参与“签约起算”推算，但在说明和证据中明确其不代表全部盖章生效日。
- 低置信度或印章遮挡日期自动标为人工复核。
- 每个非空抽取字段尽量保留来源文件、PDF 页码、原文、OCR/字段置信度与冲突说明。
- 合同级 JSON 断点续跑、OCR 缓存、单合同重跑、强制重跑。

## 日期规则

默认配置位于 `config/default.json`：

- `signing_date_policy = latest_recognized`：多个签约日期候选中采用最晚的已识别日期作为合同签约日期。
- `allow_partial_signing_date = true`：允许部分签约方日期参与签约起算推算。
- 部分日期缺失会保留说明，不声称该日期就是三方全部盖章后的法律生效日。
- 签章增强 OCR 置信度低于阈值时，`签约日期需人工确认=是`。

规则抽取是可审计的初筛工具，不替代人工法律审查。建议重点复核签章页、生效条件、工作日计算和模糊扫描件。

## 人工纠正

网页首页的“人工纠正识别结果”支持按项目、合同和字段保存人工确认值。合同标识使用：

- `前向`：前向合同及附件合并结果；
- `后向:001`、`后向:002`：按后向目录文件名排序后的第1、第2份后向合同。

纠正记录保存在 `contract_review.db` 的 `field_corrections` 表中，重新OCR不会覆盖。保存或删除纠正后，系统会基于OCR缓存自动重新计算审查结果。工期没有明确数字时，“工期数值”保持为空，并通过“工期提取结论”和“工期计算状态”反馈“随道路建设周期”“双方另行确认”或“按招标文件及投标文件执行”等非量化约定。

人工补录合同签订日期后，系统会按照合同起算条款联动更新起算日期、预计完成日期及可计算的到货、初验、终验节点。例如起算方式为“合同签订开始”、工期为6个月时，预计完成和无独立明确日期的终验节点按签订日期顺延6个月。若合同约定“甲方通知后”或“收到开工令后”起算，签订日期不会替代通知/开工令日期，需继续补录实际起算日期。OCR节点日期早于项目起算日期，或终验日期早于整体完成日期时，将被标记为时间异常并重新联动推算。

合同概览采用精简展示：签订、到货、初验、终验能计算时只显示具体日期；合同完全未约定时显示“合同中无明确规定”；合同提到节点但无法形成明确日期时显示“合同提及该节点，未明确日期”，不把验收后的付款期限误作验收时间。工期有数值时只显示“数值+单位”，无数值时显示简洁的引用文件或另行约定说明。

“工期与时间节点”按每一份后向合同分别审查项目完工、到货、初验和终验日期。前后向均有可靠日期时直接计算天数差：后向日期晚于前向日期即标记高风险并说明晚多少天；后向不晚于前向则标记无风险。任一侧缺少可靠日期时标记待确认，不以模糊条款代替具体日期。

“工期与时间节点”页面支持按审查事项和风险等级组合筛选。审查事项根据项目实际结果动态生成，包括工期、起算条件、到货、初验、终验等；风险等级支持高风险、中风险、待确认和无风险，两个条件同时选择时仅显示同时满足的结果。

项目详情顶部的风险指标卡仅统计中风险和高风险记录，不把待确认、无风险或普通解析提示计入数字；合同数量仍展示项目内实际合同总数。

首页汇总指标及项目列表中的未覆盖设备、工期风险、实施差异和待复核数字使用同一中高风险统计口径；项目总数、完成数、失败数和高风险项目数仍按项目状态统计。

页面默认直接展示正常后向合同的工期与节点结果；名称中含“补充合同”的结果统一收纳在折叠区，默认关闭，并显示补充合同数量和审查结果条数，点击后可展开查看和编辑。

合同概览同样将补充合同解析结果统一折叠：前向合同和正常后向合同直接展示，补充合同默认收起，展开后仍可查看签订日期、工期、到货、初验、终验并进行人工编辑。

合同概览中的到货、初验、终验日期仍只展示最终日期；日期旁的信息图标用于按需打开“日期计算依据”侧边窗。侧边窗独立展示基准日期、相对期限、计算公式、合同原文和证据页码，关闭后不占用主表空间，也不会作为额外字段进入导出表格。

签订日期和工期也采用相同的按需依据入口。若字段来自人工纠正，依据侧边窗优先标识“人工纠正”，显示修改日期和纠正说明；系统计算或合同文本识别结果则分别展示计算链路或原文证据。所有合同在结构化解析后都会执行时间联动，因此已明确起算日期和整体工期、且没有独立终验期限的合同，会将预计完成日期同步作为终验推算日期。

工期依据优先读取“工期原文”证据，而不是仅依赖结构化摘要；侧边窗分别展示识别值、提取结论、来源文件及页码、识别方式和合同上下文原文，确保数值工期可以追溯。

工期依据侧边窗展示“合同依据（字段完整原文）”和“上下文原文”两个层次，不再使用地址、保密或不可抗力等无关片段。证据回填前会核对证据数值与最终工期数值是否一致；发生“150天/50天”一类冲突时保留经过结构化确认的条款并进入证据复核，不用冲突OCR覆盖结果。

“终验后若干工作日内付款”等条款约束的是付款期限，不作为终验日期，也不会阻止系统按整体工期完成日推算终验。只有明确写出终验自身的基准事件和相对期限时，才按该独立终验条款计算。
